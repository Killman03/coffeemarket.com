# Встраивание в coffeemarket.kg

Версия 1.1.0 содержит отдельный виджет. Он использует ту же форму, формулы,
валидацию и адаптер каталога, что и опубликованный прототип.

## Обычный HTML-шаблон

```sh
npm ci
npm test
npm run build:widget
```

Скопируйте **весь** каталог `widget-dist` в статические ресурсы существующего
сайта, например `/static/coffee-calculator/`. Не переименовывайте хешированные
JS-файлы: это общие зависимости и отдельный модуль графика. `index.html` —
готовый пример встраивания, который можно открыть через любой HTTP-сервер.

В шаблоне магазина добавьте:

```html
<link rel="stylesheet"
      href="/static/coffee-calculator/coffee-market-calculator.css" />

<div id="coffee-calculator"></div>

<script type="module">
  import { mountCoffeeCalculator } from
    '/static/coffee-calculator/coffee-market-calculator.js';

  const unmount = mountCoffeeCalculator(
    document.getElementById('coffee-calculator'),
    { headingLevel: 2 }
  );

  // Если клиентский роутер удаляет страницу, перед удалением вызвать unmount().
</script>
```

Виджет сам содержит необходимые браузерные зависимости. Глобальные React,
jQuery, Bootstrap, Next.js, сервер Sites и вход через ChatGPT ему не нужны.
Никакого iframe нет. Существующие шапка, навигация, хлебные крошки и подвал
магазина остаются в шаблоне. Виджет не создаёт собственные `html`, `body`, `main`,
магазинную навигацию или футер.

Если заголовок уже нарисован шаблоном:

```js
mountCoffeeCalculator(element, { showIntro: false });
```

В новом разделе страницы используйте `headingLevel: 2` (значение по умолчанию
для JS-виджета). Если калькулятор сам является заголовком всей страницы,
задайте `headingLevel: 1`.

## Стили и адаптивность

Дизайн согласован с текущим coffeemarket.kg: `#DA9F5B`, `#33211D`, `#FFFBF2`,
Montserrat для текста и Roboto для заголовков. В виджете шрифты берутся из
магазина; при их отсутствии используются системные. Самостоятельная страница
предпросмотра поставляет эти шрифты локально через Fontsource.

CSS Modules генерирует изолированные имена классов. Внутренние сбросы стилей
ограничены корнем калькулятора. Виджет не импортирует глобальный Bootstrap,
Tailwind preflight или `app/globals.css`, не меняет `:root` и `body` хоста.
Ширина определяется контейнером, а не только экраном: container queries
перестраивают колонки на 850 и 600 px, поэтому калькулятор можно поместить
в более узкую область десктопной страницы. Минимальная проверенная ширина
контента — около 340 px.

Тему можно уточнить на родительском контейнере:

```html
<div id="coffee-calculator" style="
  --cmc-accent: #DA9F5B;
  --cmc-accent-dark: #925B26;
  --cmc-ink: #33211D;
  --cmc-surface: #FFFDF8;
  --cmc-font-body: 'Montserrat', sans-serif;
  --cmc-font-heading: 'Roboto', sans-serif;
  --cmc-sticky-top: 72px;
"></div>
```

`--cmc-sticky-top` — фактическая высота закреплённой шапки магазина. Если шапка
не закреплена, оставьте 0 px. Мобильный блок результата использует `sticky`
внутри калькулятора, а не `fixed` на всей странице. Родитель с `overflow: hidden`
или `overflow: auto` может изменить его поведение — проверьте это в шаблоне.
Не применяйте к виджету широкие правила хоста с `!important`.

Все поля и связанные с ними label/aria-describedby имеют уникальные ID.
Независимые JS-монтирования получают собственный React identifierPrefix.
Точные суммы не скрываются в графике: рядом остаются таблицы и текстовые итоги.

## Подключение актуального каталога

Без параметра `catalog` загружается помеченный снимок от 09.11.2026. Для своего
источника передайте публичный объект, соответствующий `catalogSchema`:

```js
mountCoffeeCalculator(element, {
  headingLevel: 2,
  catalog: publicCatalog
});
```

Схема и пример структуры — `src/domain/catalog.ts` и
`src/infrastructure/catalog.snapshot.json`. Нужны цена **за упаковку**, явная
масса в граммах, остаток, ссылка и даты. Переданный объект проверяется Zod
до монтирования. UI и формулы от способа получения данных не зависят.

MCP-доступ из чата не переносится в браузер. Каталог должен отдавать ваш backend
или серверный адаптер; приватные ключи и CRM-данные в HTML не передаются.
Для другого источника переименуйте фиксированное поле `source` схемы и
согласуйте подпись происхождения в UI — не выдавайте API за MCP-снимок.

## Если существующий frontend уже использует React

Можно импортировать `Calculator` из `src/presentation/Calculator.tsx` и передать
ему проверенный `Catalog`. CSS Module подключит ваш bundler:

```tsx
<Calculator catalog={catalog} headingLevel={2} showIntro={true} />
```

Проверенная версия React — 19.3.1. В этом варианте общая копия React принадлежит
приложению хоста. `StorefrontPreview` используется только самостоятельной
страницей и не нужен при встраивании.

## Приёмка в действующем магазине

Проверьте загрузку всех JS/CSS-файлов и шрифтов, адаптацию в выбранном контейнере,
отступ sticky-блока от настоящей шапки, работу ссылок каталога, актуальность
цен и сохранение сценария на новом origin. Ключ браузерного хранилища сохранён
совместимым с предыдущей версией; перенос между доменами — через JSON.
Это инструкция для разработчика: действующий coffeemarket.kg в этой работе
не изменяется.
