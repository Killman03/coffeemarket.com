# Репозиторий Coffee Market

## Назначение

Этот репозиторий хранит исходники самостоятельного калькулятора, тесты, SQL-миграции, Excel-шаблон и документацию. Продуктовая версия — 2.2.0. Подготовка репозитория не означает выпуск новой версии сайта или завершённый перенос серверных функций.

Доменный слой, расчёты, UI и API-контракты сохраняются. Перед переносом на обычный сервер требуется реализовать PostgreSQL-адаптеры настроек, аналитики и выдачи, Node.js composition root и независимую серверную авторизацию. Текущие D1/SQLite-миграции нельзя напрямую применить к PostgreSQL. Подробности — ARCHITECTURE.md, DEPLOYMENT.md, docs/ADMIN.md и docs/ANALYTICS.md.

## История и происхождение

Основной репозиторий — [Killman03/coffeemarket.com](https://github.com/Killman03/coffeemarket.com), выбранный владельцем. На момент подготовки он публичный: все отправляемые исходники и история доступны читателям GitHub.

Исходная история Sites сохранена, включая опубликованный commit `6617941d403d42433beb8c24d9df3a1e36fff739` версии 2.2.0. После него идёт отдельный commit подготовки репозитория. Начальный GitHub commit с README сохраняется при объединении историй без force-push. Привязка origin использует обычный URL без credentials.

Файл `.openai/hosting.json` содержит идентификатор существующего Sites и объявление D1 binding; это не секрет и не доступ к облачной базе. Для воспроизведения существующего проекта он сохранён. Не создавать новую Sites-публикацию из этого репозитория без явного выбора проекта. В свою БД данные Sites не переносятся через Git.

Git не содержит node_modules, сборки, .env, .dev.vars, приватные ключи, базы данных или локальное состояние Sites/Wrangler. Демо-XLSX в public/templates — версионируемый продуктовый ресурс. Локальные файлы исходной рабочей папки не копируются в новый checkout. Секреты проверяются Gitleaks по всей истории; сканер не заменяет проверку данных и прав доступа.

## Локальная разработка

Установить Node.js версии из `.node-version`, открыть корень репозитория:

```sh
npm ci
npm run typecheck
npm test
npm run dev:portable
```

Публичный калькулятор доступен на http://127.0.0.1:3000 без секретов. Полный Sites preview требует локальной D1 и mock identity, описанных в DEPLOYMENT.md. `.env.example` поясняет границы standalone; `.dev.vars.example` содержит только опубликованные в документации значения локального mock-входа. Эти файлы не являются production-конфигурацией.

Проверить артефакты перед изменением ветки main:

```sh
npm run build:widget
npm run build:portable
npm run build
```

## Работа с GitHub

Получить рабочую копию:

```sh
git clone https://github.com/Killman03/coffeemarket.com.git
cd coffeemarket.com
```

Публичное чтение не требует токена. Для записи нужен авторизованный аккаунт с правами на репозиторий. Открытую лицензию выбирать только по решению владельца; публичность репозитория сама по себе не задаёт лицензию на продукт.

Для первой отправки подготовленной локальной копии:

1. Проверить выбранный репозиторий, его видимость и существующие коммиты.
2. Авторизовать обычный Git через Git Credential Manager или SSH. Не включать токен в URL, скрипт, Git config или командную строку. Доступ коннектора GitHub не означает, что локальный Git уже авторизован.
3. Если origin ещё отсутствует, добавить выбранный URL; затем отправить main из корня проекта:

```sh
git remote add origin https://github.com/Killman03/coffeemarket.com.git
git push --set-upstream origin main
```

Если на сервере уже есть коммиты, сначала fetch и review истории; не использовать force-push для преодоления конфликта. Не отправлять `--mirror` в существующий пользовательский репозиторий. После первого импорта каждое изменение оформлять отдельной веткой и pull request.

4. Проверить успешный GitHub Actions run именно для отправленного commit. В Settings → Rules настроить защиту main, запрет force-push и обязательные проверки `Tests and builds` и `Git history secret scan`, если тариф поддерживает эти правила для приватного репозитория. Изменения вносить через feature branch и pull request.

## CI и обновления

`.github/workflows/check.yml` устанавливает зависимости по lockfile, проверяет TypeScript и тесты, собирает widget, Node standalone и Sites Worker. Отдельная задача проверяет полную историю Gitleaks. Actions закреплены на commit SHA, доступ GitHub token ограничен чтением, checkout не сохраняет credentials. У Gitleaks закреплены версия и SHA-256 архива. Ни workflow, ни проверки не запрашивают production-секреты и не публикуют сайт.

Dependabot предлагает обновления npm и GitHub Actions раз в неделю. Их нужно проверять, а не автоматически объединять. Версию Gitleaks и SHA-256 обновлять вместе после сверки официального release. Изменение Node.js отражать в `.node-version`; проверить совместимость Dockerfile и engines package.json. `npm audit` запускать отдельно перед выпуском и при обновлениях: состояние реестра меняется независимо от кода.

## Резервная копия Git

Доставленный `.bundle` содержит историю ветки main и позволяет восстановить репозиторий без GitHub:

```sh
git clone coffee-market-calculator.bundle coffee-market-calculator
```

После восстановления удалить локальный origin bundle и подключить проверенный URL GitHub. Дополнительный ZIP содержит только отслеживаемое дерево конкретного commit, без истории и .git. SHA-256 и commit SHA перечислены в сопровождающем JSON manifest. Базы данных, настройки production и секреты требуют отдельного резервного копирования.
