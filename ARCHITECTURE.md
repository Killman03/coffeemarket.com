# Архитектура Coffee Market 2.2

## Продукт и границы

Самостоятельный сайт, русский интерфейс. Бесплатный калькулятор одного напитка даёт себестоимость, месячный результат, безубыточность и чувствительность к спросу. Профиль рынка не является источником экономических или налоговых ставок. Рынок и валюта независимы.

Профили: Кыргызстан, Казахстан, Узбекистан, Россия, другая страна. Валюты: KGS, KZT, UZS, RUB, USD, EUR, JPY, KWD. Для нового ручного сценария используются небольшие демонстрационные суммы в выбранной валюте и 20 чашек в день. Настройки находятся в src/application/demo-prices.ts. Это условные примеры, а не рыночные цены, валютная конвертация или минимальные требования к бизнесу. Неприменяемые ингредиенты и неподтверждённый налог сохраняют корректный ноль. Сохранённые сценарии, включая явно введённые нули, не перезаписываются; кнопка сброса загружает новый пример. Автоматической конвертации нет. Только KG/KGS может использовать помеченный снимок публичного каталога от 09.11.2026. Цена каталога не является внутренней закупочной стоимостью.

## Зависимости

На Node.js `ServerAuthentication` в `src/server/auth-contracts.ts` отделяет прикладную проверку владельца от Better Auth. `src/server/node/authentication.ts` адаптирует PostgreSQL/Drizzle-сессии к identity; `app/admin/dependencies.ts` выбирает Node или Sites без доверия к клиентским identity-заголовкам. Учётные записи создаются только CLI, вместе с singleton owner и аудитом в одной транзакции. Миграции auth находятся отдельно от D1 в drizzle-postgres. Секреты не передаются UI, расчётные формулы не зависят от авторизации. Полный контракт и эксплуатация — [docs/NODE_AUTH.md](docs/NODE_AUTH.md).

```text
app/page.tsx -> presentation -> application -> domain
                       infrastructure -> domain/application
app/api/* -> server/delivery -> repository and Telegram ports
worker/index.ts -> runtime composition -> D1 adapter + HTTP Telegram adapter
server/runtime -> infrastructure/pnl-workbook -> trusted XLSX template
```

- `src/domain/calculator.ts`: Zod + Decimal.js, без UI, ORM и хостинга. calculate(input, precision) принимает 0–3 знака валюты; промежуточные расчёты не округляются.
- `src/domain/markets.ts`: проверенные коды, названия, точность валют из Intl, совместимость каталога.
- `src/domain/contact.ts`: единая проверка телефона libphonenumber-js и точный текст согласия для UI и сервера.
- `src/application/scenarios.ts`: рецепты, стартовые значения, сравнение спроса, версия переносимого сценария.
- `src/infrastructure/scenario-storage.ts`: инъецируемый Web Storage. Ключ отдельный для каждой пары рынок/валюта; активный контекст хранится отдельно.
- `src/presentation`: React, React Hook Form, Zod resolver, CSS Modules, Recharts. Компоненты не содержат денежных формул. Рынок и валюта переключаются после явного подтверждения.
- `src/server/delivery.ts`: HTTP-сценарии выдачи, независимые от Sites/D1; стандартные Request, Response, fetch и Web Crypto.
- `src/server/contracts.ts`: порт постоянного хранилища и схемы API.
- `src/server/d1-repository.ts`: изолированный адаптер D1 с подготовленными запросами и атомарными переходами состояний. SQL проверяется на реальном SQLite.
- `src/server/runtime.ts`, `worker`: composition root, секреты в request-scoped AsyncLocalStorage. Нет глобальной изменяемой авторизации, токенов в клиентском коде или platform-specific кода в расчётном ядре.

## Деньги и формулы

Ингредиенты на порцию: цена за кг/литр × расход в граммах/мл / 1000.
Сырьё с потерями = ингредиенты / (1 − доля потерь).
Производственная себестоимость = сырьё с потерями + упаковка + прочие на чашку.
Комиссия и заданный налог с выручки = цена продажи × соответствующая ставка.
Маржинальный доход = цена − производственная себестоимость − комиссия − налог.
Объём = чашек в день × рабочих дней.
Результат месяца = маржинальный доход × объём − постоянные расходы.
Безубыточность = ceil(постоянные расходы / маржинальный доход), затем ceil(/дни).
При неположительном маржинальном доходе безубыточность недостижима. Неопределённые отношения возвращают null. При нулевых продажах постоянные расходы сохраняются.

Decimal.js: precision 32, ROUND_HALF_UP. До отображения суммы не округляются. Денежные итоги используют minor units выбранной валюты; проценты форматируются независимо от валюты. Налоговая модель — только введённый процент выручки; НДС и налог на прибыль автоматически не рассчитываются.

## Сценарии и миграция

JSON v2 содержит version, context {market,currency}, input, savedAt. Старый v1 всегда мигрирует в KG/KGS. Неизвестная версия отклоняется. Импорт проверяется Zod и ограничен 100 KB. При переключении валидный текущий сценарий сохраняется; при недоступном Storage остаётся сессионная копия. Ошибочные поля не теряются: переход блокируется до исправления. Язык и формат остаются русскими.

## Excel

Четыре листа: P&L, Сценарии, План-факт, Данные. Ровно три последовательных месяца и итог периода. Шесть строк меню; из сайта заполняется только исходный напиток. Все дополнительные значения пользователь вводит явно. Сценарии управляют одним расчётным блоком через единый selector, начальные множители равны 1. Пустой факт отличается от введённого нуля.

Шаблон авторится Artifact Tool и проверяется пересчётом/рендером. Из-за несовместимости namespace его один раз пересериализует стандартный openpyxl на этапе авторинга. В production работает только ExcelJS: персонализирует доверенный XLSX, сохраняет редактируемые формулы, удаляет старые кеши и задаёт fullCalcOnLoad. Excel/LibreOffice пересчитывает файл при открытии; просмотрщик без движка может не показать результаты.

Формулы Excel неизбежно представлены формулами таблицы; их соответствие ядру подтверждается независимой сверкой и проверкой реального экспортированного файла. Покупка оборудования и тело кредита не входят в P&L. Амортизация и проценты — отдельные вводимые расходы. Прибыль не является остатком денег.

## Telegram и контакты

Сайт не имитирует ручную выдачу. После явного согласия и номера создаётся непрозрачный одноразовый код на 15 минут. Telegram-ссылка открывает личный чат менеджера с подготовленным сообщением. Только отправленное клиентом сообщение запускает Business Bot; проверяются connection id, владелец и право отвечать. Файл сопровождается указанием автоматической генерации.

Сохраняются согласие с версией и временем, номер и расчёт. Номер синтаксически проверен, но владение им без OTP не подтверждается. Согласие на рекламу не запрашивается. Нет публичной выгрузки заявок. Webhook защищён секретом, тела запросов ограничены, коды хешируются, применены квоты и SQL compare-and-set. Неопределённый результат отправки не повторяется автоматически. Детали подключения и очистки — docs/TELEGRAM.md.

## Переносимость

Калькулятор и Excel не зависят от Sites. Node standalone подключает реализованные PostgreSQL-адаптеры при startup через instrumentation.ts. Порты вынесены отдельно; runtime-context предоставляет один Node runtime для route bundles и request-local bindings для Sites. Схема db/postgres/schema.ts и миграции drizzle-postgres отделены от SQLite. Независимая авторизация остаётся следующим этапом; Node не доверяет заголовкам Sites. Интерфейс и расчётное ядро сохранены. Конфигурация, транзакции, права и проверки — docs/POSTGRESQL.md. Ни sys.path/PYTHONPATH, ни runtime-модификации библиотек не используются.

## Настройки и администрирование

Домен src/domain/site-settings.ts задаёт строгую версионированную Zod-схему, нормализованные адреса, шаблон сообщения и публичную проекцию PublicSettings. src/application/site-settings.ts создаёт независимые стартовые наборы. src/application/public-calculator-settings.ts выбирает их по валюте без конвертации и каталожной подмены. UI принимает PublicSettings как данные; browser storage посетителя имеет приоритет.

src/server/settings-repository.ts реализует SettingsRepository через D1 prepared statements. Три таблицы site_owner/site_settings/site_settings_audit создаёт миграция 0001; прежний SQL неизменён. Полный документ настроек имеет version=1 и revision для CAS. Запись настроек и аудит метаданных атомарны через D1 batch; проигравший конкурент получает null/HTTP409. Аудит не хранит копии контактов или секретов. Порты допускают PostgreSQL-реализацию со стандартной транзакцией и UPDATE WHERE revision.

src/server/admin.ts содержит проверку владельца, CSRF и сценарии HTTP, независимые от Next/Sites. app/admin/dependencies.ts — единственная связка с официальным Sites auth helper app/chatgpt-auth.ts. Проверка доступа повторяется в API, а не только в UI. Публичная страница динамическая, получает только content/defaults; конфигурация доставки читается заново из БД. HTTP ответы API no-store, тела ограничены, валидация клиент/сервер одна. Админка не принимает HTML и не раскрывает токены.

Identity gateway Sites обязан удалять клиентские oai-authenticated-user-* и подставлять проверенные заголовки. Эти заголовки нельзя считать доверенными при прямом запуске произвольного Node-сервера. Переносимый калькулятор доступен без БД; админка на таком сервере закрыта до подключения identity/storage адаптеров. В Django используйте существующие authentication, staff permissions, CSRF middleware и ModelAdmin для эквивалентных настроек; интерфейс можно перенести, но копировать доверие к внешним заголовкам нельзя. Детали — docs/ADMIN.md.

## Собственная аналитика 2.2

Контракты и UTC-периоды отделены в src/domain/analytics.ts; порт AnalyticsRepository имеет ingest/report/cleanup, D1-адаптер — src/server/analytics-repository.ts. BrowserAnalytics принимает только имя события и MarketContext, не финансовые значения. Provider доступен только публичной странице; widget без provider не отслеживается. Owner exclusion проверяется на сервере страницы и коллектора.

Миграция 0002 добавляет sessions/events и nullable связь с delivery-заявкой. Уникальный eventId и D1 batch дают атомарную дедупликацию; повторы не продлевают активность. Отчёт — SQL-агрегаты, UTC-когорта с неизменяемой атрибуцией и последовательной воронкой. Подтверждённые показатели читают реальные состояния pnl_requests. UI не может отправить событие delivered. Полная семантика, ограничения, очистка и перенос — docs/ANALYTICS.md.
